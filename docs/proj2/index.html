1.1

Convolution from scratch

Almost everything in this project starts with convolution: I slide a small filter over an image, multiply it by the pixels underneath, and use the sum as the new pixel value. I flip the filter before doing that; leaving it as-is would give cross-correlation instead.

I wrote two versions to see what the loops cost. One uses four loops, with two for the output pixels and two for the filter, while the other lets NumPy handle the filter-sized patch inside the two outer loops.

Four loops

def convolve_four_loops(image, filter, mode='same'):
    flipped_filter = np.flip(np.flip(filter, axis=0), axis=1)
    image_h, image_w = image.shape
    fh, fw = flipped_filter.shape

    if mode == 'same':
        pad_top = fh // 2
        pad_bottom = (fh - 1) // 2
        pad_left = fw // 2
        pad_right = (fw - 1) // 2

    elif mode == 'full':
        pad_top = pad_bottom = fh - 1
        pad_left = pad_right = fw - 1

    else:
        raise ValueError("mode must be 'same' or 'full'")

    padded = np.pad(
        image,
        ((pad_top, pad_bottom), (pad_left, pad_right)),
        mode='constant'
    )

    output_h = padded.shape[0] - (fh - 1)
    output_w = padded.shape[1] - (fw - 1)
    output = np.zeros((output_h, output_w))

    for i in range(output_h):
        for j in range(output_w):
            for fi in range(fh):
                for fj in range(fw):
                    output[i, j] += (
                        padded[i + fi, j + fj]
                        * flipped_filter[fi, fj]
                    )

    return output

Two loops

def convolve_two_loops(image, filter, mode = 'same'):
    flipped_filter = np.flip(np.flip(filter, axis=0), axis=1)
    image_h, image_w = image.shape
    fh, fw = flipped_filter.shape

    if mode == 'same':
        pad_top = fh // 2
        pad_bottom = (fh - 1) // 2
        pad_left = fw // 2
        pad_right = (fw - 1) // 2

    elif mode == 'full':
        pad_top = pad_bottom = fh - 1
        pad_left = pad_right = fw - 1

    else:
        raise ValueError("mode must be 'same' or 'full'")

    padded = np.pad(
        image,
        ((pad_top, pad_bottom), (pad_left, pad_right)),
        mode='constant'
    )

    output_h = padded.shape[0] - (fh - 1)
    output_w = padded.shape[1] - (fw - 1)
    output = np.zeros((output_h, output_w))

    for i in range(output_h):
        for j in range(output_w):
            patch = padded[i:i+fh, j:j+fw]
            output[i, j] = np.sum(patch * flipped_filter)

    return output

What happens at the border?

Pixels near the edge don't have a full neighborhood, so I surround the image with zeros before sliding the filter over it. With same padding, the output stays the size of the input; full padding keeps every position where the filter touches the image, making each dimension 8 pixels larger for a 9 × 9 filter. The zero-filled border can darken the result slightly because those added black pixels count toward the average.

How fast is it?

I timed one run of each version with a 9 × 9 box filter on a 50 × 50 crop. All three give the same answer (checked with np.allclose).

VersionTime
Four loops0.0622 s
Two loops0.0068 s (about 9× faster)
scipy.signal.convolve2d0.0003 s (about 200× faster)

Letting NumPy handle the inner loops helps a lot, and SciPy is faster still.

Trying it on a photo of me

I ran three filters on a grayscale photo of myself. The box filter is a 9 × 9 grid of 1/81, so every pixel becomes the average of its neighborhood, which blurs. The difference filters, Dx = [1, 0, −1] and its vertical version Dy, subtract neighboring pixels. They stay near gray where nothing changes and light up at edges.

1.2

Finding edges

Now the goal is an actual edge map of the cameraman: white where there's an edge, black everywhere else. It takes three steps.

Step 1: take the derivative in each direction

Same Dx and Dy as above. Gray means no change, and bright or dark means the brightness jumps.

Step 2: combine them into one "edge strength" image

Each derivative only catches one direction, so I combine them with √(Dx² + Dy²). That's the gradient magnitude, and it's bright wherever the image changes quickly in any direction.

Step 3: pick a threshold

I turn the gradient into an edge map by marking anything above a threshold white. At 0.10 the grass overwhelms the picture, while 0.50 breaks up the tripod; 0.28, measured relative to the brightest gradient pixel, keeps the cameraman and camera fairly connected without showing quite so much grass. A few specks remain, which is why I try blurring first in 1.3.

1.3

Smoother edges with a Gaussian

The derivative picks up tiny changes in the grass along with the edges I actually want, so I blur the image first to quiet those changes while keeping the larger outlines. I used a 9 × 9 Gaussian with σ = 2, built from cv2.getGaussianKernel and an outer product.

Blur first, then find edges

Same steps as 1.2, same 0.28 threshold. The only difference is the blur at the start.

Before and after

The grass is much quieter after blurring, although the outlines get a little thicker as each edge spreads across a few pixels.

A shortcut: one filter instead of two

Convolution is associative, which means blurring and then taking the derivative is the same as convolving the Gaussian with Dx first and then running that one combined filter over the image. These combined filters are called derivative of Gaussian (DoG) filters. In the pictures below, gray is zero, light is positive, and dark is negative.

The combined filter gives the same result with one convolution per direction instead of two, which saves computation.

2.1

Sharpening

Here's the result first. The right side has crisper windows and carvings.

How it works

Blurring leaves the broad shapes and lighting but removes fine detail. If I subtract that blur from the original, I get the detail layer, which I can add back to make edges look sharper: sharp = image + α · (image − blur). The α value controls how strongly that detail shows up.

That is the easiest way to picture the process, though the code combines it into one filter, (1 + α) · impulse − α · Gaussian, before convolving with the image.

How much is too much?

As α goes up, the windows and carvings stand out more, but at 3 the bright halos around the dome and trees start looking unnatural.

Can sharpening undo a blur?

Here I blurred the photo on purpose first and then sharpened the blurry version.

The edges get some contrast back, but the small carvings (and the forest's branches) stay merged, because sharpening can only boost detail that's still in the image. It makes edges look crisper, but it can't undo a blur.

My own example: the Moon

The Moon photo was a little soft, so sharpening brings out the craters.

Up close, α = 1.5 makes the crater rims pop, while α = 3 just makes the surface look harsh.

2.2

Hybrid images

A hybrid image changes as you step away from it. Close up, your eye catches fine details such as fur and whiskers, but from a distance those details disappear and the broader shape takes over.

I make one by combining the detail from one photo with a blurred version of another, just as I separated detail from blur for sharpening. The photos need to line up first, usually at the eyes, or their shapes compete and the result looks like a double exposure.

To try it yourself: look at the big image, then at the smaller copies next to it (or lean back from your screen).

Tiger up close, house cat from afar

This is my favorite pair. Up close, the tiger's stripes and whiskers take over, but when the image gets small you start to see the orange tabby's ears and pink nose instead. The switch works because both cats are orange and face the camera, so their shapes already line up reasonably well.

How it was made, step by step

1. Line them up. I picked both eyes in each photo and rotated, scaled, and shifted the cat so its eyes land exactly on the tiger's.

2. Filter them. I keep the tiger's detail (the photo minus a σ = 4 blur) and blur the cat with σ = 10, then add them. I picked the cutoffs by shrinking the result: with less tiger detail the stripes disappeared up close, and with less blur on the cat its own face kept showing through. I also boost the tiger layer 1.2× so it wins up close.

3. Check it in the frequency domain. In these log-magnitude Fourier transforms, the center represents broad changes and the outer area represents fine detail. The blurred cat stays bright near the center, while the tiger detail loses much of its center; the hybrid shows both patterns together.

Nutmeg the cat and Derek

For the assignment pair, I lined up Nutmeg's and Derek's eyes, kept the cat's detail with σ = 3, and blurred Derek with σ = 8. The whiskers and fur show up across his face nearby, but at a distance Derek's smile comes through.

2.3

Gaussian and Laplacian stacks

Hybrids use a simple split between blur and detail, but blending needs several layers so the seam can change with the size of the features around it.

Gaussian stack: I blur the image repeatedly, doubling σ at each level (2, 4, 8, ...). Every level keeps the original dimensions, which makes it a stack rather than a downsampled pyramid.

Laplacian stack: I subtract each Gaussian level from the one before it to see what detail that blur removed. The layers go from fine texture to broader color changes, with the blurriest image at the end; adding them back together reconstructs the original.

2.4

Multiresolution blending

A hard cut makes the join between two photos obvious, but simply blurring the join doesn't solve everything either: a narrow fade leaves a color jump, while a wide one overlaps fine details and looks ghosted.

I use the stacks from the previous section to give each scale its own transition. At each level I blend the two Laplacian layers with a differently blurred mask, blendk = maskk · Ak + (1 − maskk) · Bk, then add the six levels together. Fine details switch sides quickly while the larger color changes fade more gradually.

★

What I learned

The part I found coolest is that you can treat different frequencies differently. In blending, the fine details switch over quickly while the colors and big shapes fade slowly, and hybrid images use the same idea with your eyes: up close you see the high frequencies, but from farther away the details blur out and only the low frequencies are left.

I also learned that picking the right photos matters as much as the code. Most of my failed attempts had working code and a bad pair of images, and the ones I like most, like the tiger and the cat, work because the two photos already have a similar shape and color to begin with.
